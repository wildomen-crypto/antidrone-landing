# Топинженер — лендинг металлоконструкций

Продолжение с другого ПК: [инструкция](docs/HOME.md).
Живая страница: https://topengineer.ru/proektirovanie/proectirovanie-antidronovoi-zashiti.

На основную страницу перенесён выбранный вариант -4: промышленный фон
с защитными сетками сверху/по периметру, затемнение и оранжевые акценты.
Та же версия остаётся доступной по ссылке:
https://topengineer.ru/proektirovanie/proectirovanie-antidronovoi-zashiti-4.
Фото плавно переходит в однотонный графитовый фон; шапка и подвал Joomla
сохранены. Каркас по умолчанию светлый; двухцветный круг рядом с кнопками вида
переключает каркас и оттяжки на прежние цвета с белым фоном 3D-сцены.
Повторное нажатие возвращает светлый каркас и тёмную сцену. Сетки остаются прежними; выбор цвета
не влияет на стоимость и действует до перезагрузки страницы.
Ресурсы/готовые вставки статей — joomla/design-variants,
границы и проверка переноса — docs/checkpoints/PROMOTE-INDUSTRIAL-MAIN-20261006.md.
Размещение и откат: [docs/deployment-topengineer.md](docs/deployment-topengineer.md).

В текущем исходном коде карточки портфолио и материалов используют отдельные
адаптивные WebP-превью. Оригинальные PNG открываются в галерее поверх страницы:
в Joomla — существующий Widgetkit сайта, самостоятельно — доступный HTML dialog.
Превью уже включены в репозиторий; повторная подготовка при замене изображений:
`python scripts/prepare-photo-previews.py` (нужен Pillow). Скрипт сохраняет оригиналы.

Готовый установочный модуль Joomla 1.1.1 (ZIP для Linux-хостинга):
[скачать из Releases](https://github.com/wildomen-crypto/antidrone-landing/releases/tag/joomla-v1.1.1).

Отдельная версия `/joomla` предназначена для страницы существующего
topengineer.ru (Joomla 3.10.12, yoo_monday). Использует его шрифты и оформление,
общий 3D-конструктор и цены. `npm run build:joomla` создаёт установочный ZIP
без Node на хостинге. Инструкция и границы проверок — [docs/joomla.md](docs/joomla.md).

Локальный сайт на Next.js, React, TypeScript и Three.js. Каталог C1–C8,
параметрическая 3D-компоновка, геометрическая ведомость, заявки в SQLite,
JSON и печатная карточка. Контакты берутся из config/company.ts.

По просьбе пользователя введена черновая цена проектирования по трудоёмкости:
1250 ₽/ч, отдельные часы КМ/КМД/КЖ. По запросу цены переведены в RUB:
это округлённый эквивалент прежних 15 $/ч по курсу ЦБ 83,4839 ₽/$,
действующему с 03.10.2026 и проверенному 05.10.2026. Ставка фиксирована
в настройках; автоматического обновления по курсу нет.
Размеры, форма, элементы/опоры, заполнение и основание влияют на оценку.
Настройки — config/project-pricing.ts, методика и контрольный пример —
docs/project-price.md. Коммерческие тарифы пока не подтверждены.
Это предварительная компоновка, не расчёт прочности или эффективности
защиты. Узлы, сечения, шаг труб/сети и основания показаны условно.

Первым под шапкой расположен 3D-конфигуратор. Верхняя форма заказа удалена.
Под параметрами и выбором КМ/КМД/КЖ расположена форма #quote-request:
отдельные телефон и email, ФИО и описание задачи. Подсказки только внутри
полей; доступные названия сохраняются после ввода. Город убран из обеих форм.
Для связи нужен телефон или email; можно заполнить оба, они сохраняются
раздельно. ФИО и описание необязательны. Поля в четыре колонки,
до 1100 px в две, до 500 px в одну. Согласие и кнопка «Получить проект»
завершают форму; кнопка отправляет текущую валидную схему и услуги.
После этапов работы восстановлен блок #contacts «Обсудим конструкцию
и состав работ»: телефон, email, проектирование, адрес и график слева,
форма «Обсудим ваш проект» справа (на телефоне друг под другом).
Нижняя форма принимает обычную заявку без 3D-схемы; согласие и поля
независимы от формы конфигуратора. Подробные контакты постоянно видны.
Ссылка «Контакты на основном сайте» убрана из контактного блока.
За конфигуратором идёт каталог решений. В карточках каталога
пояснение является ссылкой выбора соответствующей формы в 3D;
отдельной строки «Настроить схему» нет. Рамки схем C1–C8 одинаковой высоты:
140–180 px на широком экране, 150 px на 501–767 px, 90 px на телефоне.
Поля внутри SVG уменьшены только в каталоге; схемы показаны целиком.
Повторный вводный
блок с навесом удалён по запросу пользователя. Якорь #calculator сохранён.
Также удалены блоки «От исходных данных до рабочих чертежей»,
«Продуманная схема. Точные чертежи.» и «Что стоит уточнить».
После материалов идут состав документации и этапы работы.
Вертикальные поля разделов уменьшены до 32 px на компьютере и 24 px
на узком экране; промежутки между соседними разделами — 64 и 48 px.
Ссылка «Услуги» на удалённый раздел исключена из меню.

Сайт предлагает проектирование: разработку КМ, КМД и КЖ. Изготовление,
доставка и монтаж не предлагаются. Эти три раздела независимо выбираются
в «Нужных работах»; по умолчанию отмечены КМ и КМД. Выбор сохраняется
в JSON, черновике и заявке как km, kmd, kzh и выводится в печатной карточке.
Старые JSON/черновики сохраняют геометрию и материалы. Прежние услуги
design/manufacturing/supply/delivery/installation удаляются с пояснением
в интерфейсе; новые разделы необходимо выбрать вручную. Версия JSON — 1.

На странице есть галерея #portfolio с восемью примерами возможной реализации C1–C8.
Фотореалистичные изображения созданы через ImageGen и подписаны как визуальные

Изображения: public/images/portfolio и public/images/refinery-protection-concept.png.

В #materials размещены восемь собственных фотореалистичных визуализаций,

Карточки содержат фото, название и короткое описание. Подписи под фото

и не подтверждают защитные свойства; в разделе указано, что это визуализации.

## Запуск

Для оценки без установки программ: https://wildomen-crypto.github.io/antidrone-landing/.
На GitHub Pages размещена интерактивная демонстрация: 3D, цены, изображения
и оба варианта формы. Формы явно помечены и не отправляют заявки на сервер.
Обычный локальный сервер/переносимый архив сохраняют настоящие заявки как прежде.
Исходный репозиторий: https://github.com/wildomen-crypto/antidrone-landing.

`npm run build:pages` готовит статический сайт в изолированной .local/pages-копии,
с префиксом /antidrone-landing, .nojekyll и без API/приватных файлов.
Для обновления Pages содержимое указанного out размещается в ветке gh-pages;
main хранит исходники, Pages настроен на gh-pages /. Обычная .next не меняется.
Переменные NEXT_PUBLIC_BASE_PATH и NEXT_PUBLIC_REVIEW_MODE задаются только
сборщиком статической демонстрации; их не задавать для обычного сервера.

Для переноса на Windows 10/11 x64 без установленного Node/npm есть упаковщик:
`node scripts/package-portable.cjs`. Он создаёт в .local/portable ZIP с готовой
standalone-сборкой, официальным Node 24.14.1 (SHA256 проверен), лицензиями,
полным исходником и START.cmd. Получателю не нужны установки/интернет.
START.cmd выбирает свободный локальный порт и открывает браузер.
Новые заявки в data, LEADS.cmd выгружает их в JSON; прежние данные/секреты
не включаются. Подробная инструкция scripts/portable/README.txt.
Режим BUILD_PORTABLE=true используется только упаковщиком; обычная сборка прежняя.

Node.js 24+, npm. На Windows PowerShell использовать npm.cmd.

```powershell
Set-Location C:\taran\antidrone-landing
npm.cmd ci
npm.cmd run dev
```

Адрес: http://127.0.0.1:3100. Сервер доступен на этом компьютере.
Не запускать dev и start одновременно на одном порту.

Варианты интерфейса: `/` — компактный конфигуратор с боковой панелью;
`/wide#calculator` — сцена на всю ширину, выбор формы по картинкам сверху,
ползуны размеров и точный числовой ввод сверху слева поверх 3D;
там же ползунки максимального шага секций (1–10 м) и числа слоёв (1–3).
Ширина левой панели — 190 px, точных полей — 32 px; на мобильном поля
40 px, панель ограничена доступным местом и максимумом 190 px.
Под ними — иконки 20×20 для сечения, основания и сторон. На узком экране
левая панель прокручивается. Основания: блок или сваи с ростверком;
сваи без ростверка исключены также из контуров и импорта.
Карточки пространственной опоры и фермы можно выбрать вместе; отдельного
флажка опор нет. В /classic это сочетание доступно в списке несущих элементов.
Кровля управляется её материалом: повторное нажатие активной карточки
кровли отключает покрытие, выбор материала включает. Так же работает
заполнение стен; при отключении сохраняются каркас и выбор сторон.
Начальные материалы стен/кровли — ПВЛ (M7). У круглого контура отдельной
иконки бокового заполнения нет. Старые JSON без walls читаются с walls=true,
сохраняя свои материалы; новые JSON содержат флаг walls.
У навеса и козырька покрытие
обязательно. Флажка «Включить покрытие» нет; в /classic для необязательной кровли
есть пункт «Без кровли».
У круглого контура C7 отдельного переключателя варианта нет: материал
кровли включает купол, снятие выбора оставляет открытый контур. Подъём
виден только с кровлей. Старые JSON кругового периметра импортируются
без покрытия; новые используют variant=dome и флаг roof.
Размеры активного проёма на /wide — ползунки с точным вводом в правой
панели и пределами по габаритам конструкции.
Отступы и высоты трёх контуров комплексного укрытия на /wide также
заданы компактными ползунками с точным вводом в правой панели.
Дополнительные настройки постоянно справа. Под сценой — отдельные ряды
картинок: заполнение стен (8), материал кровли (8), несущие элементы (6).
Кровля показывается для форм с покрытием; выбор её материала независим
от стен. На узких экранах ряды прокручиваются горизонтально.
Модель кадрируется в свободной области
между панелями или ниже размеров. Высота сцены одинаковая.
Ссылки сравнения убраны из интерфейса; сайт показывает основную компоновку.
Основной адрес `/#calculator` теперь показывает принятую overlay-версию.
`/overlay` остаётся её дополнительным адресом; старая боковая компоновка
перенесена на `/classic#calculator`. Проём в основной версии без
внутренней обводки/заливки, ползунки на общей поверхности панели.
В основной версии под материалами — стоимость, работы и кнопка получения
расчёта. Ведомости/детальные схемы сохранены только в сравниваемых версиях.
Кнопка «Получить проект» отправляет контактные поля с текущей конфигурацией
на сервер. Перед отправкой сохраняется черновик схемы без контактов;
после успешной отправки черновик очищается, скачивается копия JSON схемы.
Ошибка отправки сохраняет поля и позволяет повторить тот же запрос.
Получение конфигураций: docs/RECEIVE_CONFIGURATION.md. Автоматическая
доставка в email/CRM требует настроенного получателя.
`/overlay#calculator` — отдельный вариант для сравнения: от 768 px обе
панели шириной 190 px остаются поверх 3D; высота сцены 308–434 px,
настройки прокручиваются внутри панелей. До 768 px интерфейс совпадает
с /compact. `/compact` сохраняет две колонки под сценой на среднем окне.
Проверка новой версии: `npm.cmd run test:overlay`.
Проверка широкого варианта после сборки и запуска: `npm.cmd run test:wide`.

`/compact#calculator` — адаптивная версия с тремя компоновками. Рисунки
материалов 65 px при ширине >=1280 и 32 px на узких окнах. От 1280 px
при высоте окна >650 px —
панели поверх сцены высотой 308–434 px в ширине основного контейнера сайта.
На среднем окне —
свободная сцена 238–322 px и две колонки настроек под ней. До 768 px —
последовательные блоки, сцена 210–280 px, материалы сеткой 3–4 колонки,
несущие элементы — 3. Высоты уменьшены на 30% по запросу заказчика;
короткое горизонтальное окно — 210 px. Накладные панели на большом окне
прокручиваются при нехватке высоты.
Типы конструкций тоже адаптируются: рисунки 76 px на большом окне и
32 px при ширине <1280 px; сетка как у стен — 8 колонок на среднем,
4 на телефоне и 3 при ширине <360 px, без горизонтальной прокрутки.
Ракурсы и «Только каркас» — иконки 20×20 в кнопках 32×32 прямо на сцене,
по центру снизу, с подсказками и клавиатурным управлением. Отдельной строки
под моделью нет. Размеры/состояние сохраняются при resize.
На узких экранах нет вложенной прокрутки настроек. По уточнению заказчика
отступы/числовые поля/ползунки уплотнены. Сечение, основание и стороны
выстраиваются в одну строку при достаточной ширине; иначе группы переносятся.
Проём — 144 px. Числовой шрифт 16 px,
иконки выбора 32 px; материалы и основные действия остаются >=44 px.
При вводе нижние действия скрываются; учтена безопасная область.
Несущие элементы находятся перед заполнением стен, затем кровля и работы.
Карточки типов/материалов имеют меньшие вертикальные отступы.
Передний проём включён по умолчанию в новой допустимой схеме /compact;
отключённое состояние из JSON восстанавливается без принудительного включения.
Пустая панель параметров скрыта,
а на среднем окне размеры занимают обе колонки: ползунки в 3–5 колонок,
сечение/основание справа. На телефоне без параметров ползунки в 2–3 колонки
при достаточной ширине. Если параметры появляются, компоновка возвращается.
У навеса выбор заполнения стен полностью скрыт; кровля доступна.
длинная на большом экране прокручивается в пределах сцены. `/wide` сохранён.
Проверки: `npm.cmd run test:compact` и `npm.cmd run test:responsive`
(320–2560 px, все формы, ввод, resize, JSON, печать и SVG).

Для собранной версии:

```powershell
npm.cmd run check
npm.cmd run start
```

check выполняет типизацию, независимые unit-тесты, сборку приложения и
служебной CLI. start требует готовую сборку. Остановка своего сервера: Ctrl+C.

## Что работает

- Восемь форм: экран, периметр, навес, укрытие, пристенные решения,
  галереи трёх вариантов, круглый/шатровый контур, комплексное укрытие.
- Восемь материалов с различимым рисунком. Комбинированная панель
  раскрывается в отдельные материалы и объёмы каждого слоя.
- Круглые/профильные элементы, пространственные опоры и фермы;
  три условных варианта основания, крупный просмотр типовых деталей.
- До трёх контуров с независимыми высотами, отступами, материалами,
  слоями, несущими системами и основаниями.
- Скрытие контура меняет только изображение; исключение меняет заказ.
- Три дополнительных стеновых модуля: ФБС, железобетонные панели, габионы.
- Вращение, масштаб, четыре вида, размеры и 2D при отсутствии WebGL.
- Площади и длины из общего графа. Масса и крепёж не выдумываются.
- Валидируемый JSON без контактов; печатная карточка с кириллицей,
  размерами, ведомостью, датой и контактами. PDF сохраняется через печать.
- Форма с отдельным согласием, серверной проверкой и прикреплённой схемой.
  Успех показывается после записи в БД; повторный запрос не дублируется.
- Очередь уведомлений с повторными попытками; локальная CLI для работы
  с заявками и согласованного резервирования SQLite.

## Настройки

Скопировать .env.example в .env.local. Секреты в Git не добавлять.

| Поле | Назначение |
| --- | --- |
| DATA_DIR | Постоянный частный каталог SQLite; по умолчанию .local/data |
| SITE_PUBLIC | false для локальной версии; публичный режим требует утверждённых документов |
| SITE_ORIGIN | Канонический origin публичного сайта, например https://ваш-домен; локально можно оставить пустым |
| TRUST_PROXY | true только за своим настроенным proxy, перезаписывающим X-Forwarded-For |
| NOTIFICATION_WEBHOOK_URL | Утверждённый сервер получателя; пустое значение сохраняет очередь без отправки |
| NOTIFICATION_WEBHOOK_TOKEN | Секрет интеграции, если нужен получателю |

Публичная форма закрыта при legal.approved=false. Правовые страницы —
проекты. Все страницы пока noindex. Для публикации выполнить
docs/OPERATIONS.md, утвердить документы и отдельно включить индексацию.
Одного переключения SITE_PUBLIC недостаточно для выпуска.

## Архитектура и границы

Рабочий контракт импорта и API: LayoutInput в lib/configuration/input.ts,
версия 1. Он хранит параметры форм и независимые настройки контуров.
parseInput проверяет неизвестные поля, числа, размеры и проёмы.
Изначальные нормализованные типы из ТЗ сохранены в schema.ts вместе с ID
и единицами; они не являются альтернативным форматом API/JSON.

generateModel создаёт единый граф элементов, поверхностей, опор и модулей.
Viewer, SVG и quantities используют его. Криволинейные покрытия считаются
по показанным граням; круглый купольный вариант сейчас имеет секторную
шатровую форму. Детальный просмотр — самостоятельная типовая схема,
которая не добавляет элементы в заказ.

Нельзя превращать рисунок сетки, условные профили или демонстрационный шаг
в подтверждённую характеристику изделия. compatibility.approved пуст:
все сочетания требуют проверки инженером. Тарифный контракт и чистый
движок budget.ts подготовлены и протестированы; коммерческое сопоставление
профилей/массы/работ с тарифами требует утверждённых данных.
Текущий estimate всегда возвращает ручную стоимость.

Заявка и outbox записываются одной транзакцией. Ключ повторного запроса
связан с хешем данных; изменение тела с тем же ключом даёт 409.
Отказ БД даёт ошибку, сбой получателя оставляет уведомление в очереди.
Уведомление содержит только leadId и стабильный Idempotency-Key.
Получатель должен обрабатывать повторы и иметь отдельный частный способ
доступа к данным; публичного API выгрузки заявок нет.

Загрузка PDF/CAD-файлов в форму не входит в первый выпуск. Для проекта по
чертежам показаны подтверждённые корпоративные email. Аналитика отключена;
адаптер категориальных событий не передаёт контакты, размеры и номера заявок.

## Проверки

```powershell
npm.cmd run typecheck
npm.cmd run test:unit
npm.cmd run build
npm.cmd run test:browser
```

Браузерные проверки запускать на локальном start после сборки и unit-тестов.
Требуется Playwright и Edge. В этой среде используется комплект Codex.
На другом компьютере задать PLAYWRIGHT_MODULE (имя установленного
модуля либо file: URL его index.mjs) и при необходимости PLAYWRIGHT_CHANNEL.
Скриншоты и отчёт создаются в .local/qa; это не публичные файлы.
QA создаёт синтетические заявки с qa@example.com и удаляет только свои ID.
Не подключать внешний webhook при такой проверке.

Результаты и ограничения: docs/QA.md. Браузеры Safari/iOS, Android и Firefox
нужно дополнительно проверить на соответствующих устройствах перед запуском.

## Продолжение после лимита

Сначала читать docs/STATUS.md, docs/BLOCKS.md и текущую карточку
docs/checkpoints/LOCAL-DELIVERY.md. Проверить git status и фактический код.
Сохранять законченный участок коммитом, не удалять незавершённую работу.
Наличие кода не означает VERIFIED: состояние определяется проверками.
Внешнее размещение, данные и настройки оператора имеют отдельные статусы.

разбиение и рекомендации по моделям: docs/CODEX_PLAN.md.
