# UI-RESPONSIVE-LAYOUT

Статус: VERIFIED. База: eff473a; исходный проверенный код f03a175.
Ветка: ui/responsive-layout. Запрос: три пригодные компоновки для большого,
среднего окна и телефона; проверка доступности всех настроек.

Планируемые файлы: app/responsive.css, app/layout.tsx,
components/calculator/Calculator.tsx, tests/compact-browser.mjs,
tests/responsive-browser.mjs, package.json, README, SPEC, QA,
docs/STATUS.md, docs/BLOCKS.md.

Решение: /compact — адаптивный вариант. На большом экране — полноширинная
сцена и компактные накладные панели. На среднем — свободная сцена,
панели ниже в двух колонках; на телефоне — сцена и настройки последовательно.
Состояние не теряется при смене ширины. /wide остаётся для сравнения.
Общие секции лендинга: читаемые карточки, шапка, форма и безопасные отступы.

Критерии: нет горизонтального переполнения страницы; панели вне сцены
на ширинах <1280; камера не резервирует под них пространство; все C1–C8,
материалы, проёмы и контуры доступны; на телефоне цели касания >=44 px;
точный ввод 16 px; JSON и печать сохранены. Проверки в браузере 320–2560 px,
включая низкое окно и горизонтальный телефон, визуальный просмотр
трёх основных компоновок. Typecheck/build, compact/wide и responsive QA.

Следующий шаг: CSS трёх компоновок и учёт пересечения панелей со сценой.
Публичное размещение не выполняется, внешние блоки не изменяются.

Реализация завершена, идёт финальная проверка. Отдельный responsive.css
применяет три компоновки к /compact и общие исправления лендинга.
Сцена больше прежней на больших окнах; /wide сохраняет прежнюю высоту.
Средние/телефонные панели находятся в потоке документа, переполнение не
скрывается принудительно. Материалы на телефоне все видны, размеры в
двух колонках (320 px — одна); рисунки 32 px, SVG сечения/оснований 20 px.
Камера проверяет реальное пересечение панелей, слушает resize и очищает
отступы при переносе настроек. Контролы ракурса сразу под моделью.
Мобильные нижние действия скрыты при фокусе текстового поля/select.

Типизация и build/worker PASS. test:wide 19 групп PASS, test:compact
5 групп PASS. Первый responsive-прогон прошёл 12 размеров, затем параллельно
с другими GPU-тестами не дождался Canvas; причина не установлена,
ошибок JS не было. Последовательный прогон с отдельными страницами для
групп прошёл все четыре группы. После дополнительной проверки фокуса
исправлен selector для полей с неявным type=text. Финальный прогон идёт.
Геометрия/ведомость/контракт JSON не изменялись, unit повторно не запускались.

Финальная сборка/worker и responsive QA PASS: пять групп, 12 размеров
320×640, 360×740, 390×844, 600×900, 768×1024, 1024×768,
1279×900, 1280×800, 1440×900, 1920×1080, 2560×1440, 844×390.
Во всех режимах нет overflow и ошибок JS. C1–C8 проверены на 390/1024/1920.
Resize сохраняет размеры, слои, проём, сечение, основание, опору+ферму,
работы; экспорт JSON подтверждает значения. Проверены состав комбинации,
контуры, очистка отступов камеры SVG и скрытие UI в печати.
На телефоне числовые поля и ползунки также 44 px, ввод без увеличения шрифта.
При фокусе заявки нижние действия скрыты, после blur возвращаются.

Touch QA: Chromium isMobile/hasTouch/DPR2; обычный tap выбирает материал,
меняет слои и работы, ручной CDP drag меняет изображение 3D.
После ручного CDP drag в эмуляторе пропадал следующий click; отдельный tap
на свежей странице работает с первого касания. Жест проверяется отдельно,
после элементов UI; физический телефон и Safari/Android не проверены.
Это ограничение эмуляции не скрыто заменой tap на click.

Отчёты: .local/qa/responsive/report.json, compact-materials/report.json,
wall-material/report.json. Просмотрены hero и 3D на 390/1024/1920,
мобильный купол, контуры, контакты, материалы и итоговая ведомость.
Финальный compact-regression PASS: пять групп, ошибок JS нет.
